# Private working drafts and explicit publication

New authenticated editor-drafts API uses private editor-draft:<UUID> settings keys in the existing Status D1 database. Existing public snapshot only reads public/viewer_state keys; working drafts do not change published notices, original visibility, public timestamps or viewer design. No schema migration. Existing audit triggers cover server saves and publications. Existing admin authentication, notice validation, branch stamping and cache invalidation are reused verbatim from protected v1.5.3 source.

PUT with draft revision and stable save request UUID saves incomplete private copies. POST preview validates without writing public data. POST publish validates the saved revision and atomically updates/inserts one notice plus marks its working copy published using D1 batch and optimistic revision checks. Original notice IDs/timestamps/fields are retained when editing. Saved copies retain their baseline revision; concurrent external edits cannot be silently overwritten. Replay keys prevent duplicate save/publication after an uncertain response. GET list paginates private active working copies. No delete/reopen/resolve/settings editor added here.
